# 小红书运营工作台（dsh-xhs-ops）

DeepSeek Harness 插件。工作台在侧边栏，账号授权在「设置 → 小红书账号」。

## 界面

**侧边栏「小红书运营」** —— 5 个页签：

| 页签 | 说明 |
|---|---|
| 调研 | 按关键词抓取搜索页；按角度聚类算场均互动 / 收藏赞比，给选题结论；抓不到时可导入 |
| 创作 | 模板生成草稿，**生成即自动合规自检**（合规分 + 逐条命中 + 建议），一键「发布至草稿箱」跳到发布页 |
| 发布 | 草稿箱列表 + 生成发布包（标题 / 正文 / 标签 / 检查表），复制到创作平台后人工发布 |
| 复盘 | 抓取**自己的主页**笔记数据，按区间算互动、收藏赞比、发布时间分布 |
| 评论·热点 | 五种模式：评论排名（抢前排）、关键词排名（评论命中）、热点排名（推荐流按互动排序）、**回复策略**（五类模板 + 人设 + 合规自检 + 一键复制）、**评论混动**（真人感节奏 + 舆论监测分级） |

**设置 → 小红书账号** —— 账号授权：

- 主页链接（复盘用，自动识别 user id）
- Cookie 授权（本机 0600 保存）
- **多账号矩阵**（账号池，一键切换，脱敏）
- 账号 / 密码表单（**仅界面提示，不保存、不发送**）
- 本地数据清空

## 评论运营（v0.3 新增）

### 回复策略

对已抓取/已导入的评论，按情绪自动分类（**咨询 / 负面 / 正面 / 中性 / 引流**），生成回复草稿：

- **五类策略**：咨询承接、负面危机公关（质疑→澄清 / 差评→共情担责）、夸赞巩固、中性补增量、引流跳过
- **四套人设**：专业顾问 / 亲切姐妹 / 干货老司机 / 品牌官方，统一回复语气与禁忌词
- **每条回复自动过合规自检**，命中风险词会标出合规分
- **一键复制，手动发送**——插件绝不自动回复

### 评论混动

让回复像真人运营，而非机械全回：

- **节奏规划**：按「回复比例」抽样（不全回），给出「每 N 分钟回一条 ± 随机抖动」的建议
- **优先级排序**：咨询 > 负面 > 正面 > 中性 > 引流（引流一律不回）
- **舆论监测分级**：负面聚集（≥3 条高危）、竞品/导流干扰、引流广告，三级告警

## 多账号矩阵（v0.3 新增）

「设置 → 小红书账号」里新增「多账号矩阵」：

- 给每个 Cookie 起名（主号 / 小号A …），加入账号池
- 一键切换当前账号（切换即把该账号 Cookie 写为当前抓取账号）
- 账号列表**脱敏**：对外只暴露名称/昵称，Cookie 绝不回传

## 抓取怎么工作

主路径是**页面 SSR 解析**：带 Cookie 请求页面，从 `window.__INITIAL_STATE__` 里取数据。这条路不需要 `x-s` 签名，是公开页抓取里最稳的一种。

失败时会明确回报原因：

| 原因 | 含义 | 出路 |
|---|---|---|
| `login-required` | 被重定向到登录页 | 在设置里授权 Cookie |
| `client-rendered` | 搜索页是前端渲染，HTML 里没有结果 | 在对话里说「抓取关键词：X」，由我用浏览器代抓 |
| `parse` / `empty` | 页面结构变了或笔记不存在 | 导入 |

**代理抓取**：插件本身没有浏览器权限（DSH 的 `browserUse` 只能注册唯一提供方，不能复用）。所以「登录 / 抓取」可以由我在对话里用浏览器完成，再把结果写回工作台——这是真实可用的兜底路径。

## 登录的现实

小红书网页端**没有对第三方开放的账号密码登录接口**（只有扫码 / 短信验证码，且接口需要签名）。所以：

- 表单里的账号 / 密码不会保存、不会发送，只用于说明；
- 可用路径只有两条：Cookie 授权，或在对话里说「登录小红书」由我用浏览器登录后代抓。

插件不做签名逆向，也不调用写接口。

## 明确不做

- 不自动发布、不自动评论、不自动点赞——发布只到草稿包，人工发布；回复只到草稿 + 一键复制，人工粘贴发送。
- 不绕过风控、不伪造签名。

## 数据位置

- `~/.dsh/xhs-ops/state.json`：调研数据、草稿、复盘记录、评论、回复人设与混动偏好
- `~/.dsh/xhs-ops/account.json`：当前账号 Cookie（0600）
- `~/.dsh/xhs-ops/accounts.json`：多账号池（0600）
- `DSH_XHS_OPS_DIR` 可改目录

## 自检

```bash
DSH_XHS_OPS_DIR=$(mktemp -d) node test/smoke.mjs
```

33 项：合规引擎（重叠合并、多类别、等级不降级）、调研/复盘/评论排名、模板生成、**页面解析器**（含花括号在字符串内的边界）、Cookie 归一化、ID 提取、存储读写、登录接口的诚实回报，以及**回复策略（引流识别/负面分流/合规自检）**、**评论混动（节奏/告警）**、**多账号池（增/切/删/脱敏）**。
